# دستیار پشتیبانی هوشمند 🤖

دو دستیار هوش مصنوعی روی یک مخزن دانش مشترک:

| | برای چه کسی | آدرس | لحن |
|---|---|---|---|
| 🤖 **دستیار مشتری** | کاربران و مشتریان شرکت | `/` | ساده، صمیمی، بدون اصطلاح فنی |
| 🛠 **کنسول پشتیبان** | کارشناسان پشتیبانی | `/agent` | فنی و دقیق، با ارجاع به فایل و شماره‌ی صفحه |
| 📚 **پنل مدیریت** | مدیر دانش | `/admin` | بارگذاری راهنماها، آمار، تیکت‌ها، اعتبار |

پشتیبان شرکت فایل‌های راهنما را در پنل مدیریت بارگذاری می‌کند؛ هوش مصنوعی از همان فایل‌ها
به سوال‌ها پاسخ می‌دهد — و **هیچ‌وقت از خودش چیزی نمی‌سازد**.

---

## چرا این نسخه فرق دارد

- **دو شخصیت جدا، دو سطح دسترسی.** هر فایل را می‌توانید «فقط مشتری»، «فقط پشتیبان» یا «هر دو»
  علامت بزنید. فایل‌هایی که دستور SQL و رمز و اطلاعات داخلی دارند هرگز به دست دستیار مشتری نمی‌رسند.
  دستیار مشتری علاوه بر آن، در پرامپت هم صریحاً از حرف زدن درباره‌ی دیتابیس و تنظیمات سرور منع شده است.
- **اسکرین‌شات‌های داخل PDF هم خوانده می‌شوند 👁** راهنماهای نرم‌افزاری پر از تصویر پنجره‌ها و
  دکمه‌هاست و استخراج متنیِ معمولی این‌ها را اصلاً نمی‌بیند. (در راهنمای جامعِ همین پروژه،
  ۹۵ صفحه از ۱۱۷ صفحه اسکرین‌شات دارد و در ۵۹ صفحه اطلاعات عملاً فقط داخل تصویر است.)
  موقع بارگذاری، صفحه‌های عکس‌دار به تصویر رندر و به یک مدل بینایی داده می‌شوند تا عنوان پنجره،
  نام فیلدها، دکمه‌ای که باید زده شود و پیام‌های خطا به متنِ قابل جستجو تبدیل شوند.
  همین باعث می‌شود PDFهای اسکن‌شده هم کار کنند.
- **بازسازی خودکار متن PDF.** بیشتر PDFهای فارسی متن را شکسته بیرون می‌دهند
  («سواالت» به‌جای «سوالات»، «س ی ستم» به‌جای «سیستم»). صفحه‌هایی که عکس ندارند ولی متنشان
  شکسته است، یک بار از یک مدل سبک عبور می‌کنند و متن سالم ذخیره می‌شود.
- **جستجوی ترکیبی (Hybrid RAG).** ترکیب جستجوی معنایی (بردار) و کلیدواژه‌ای (BM25) با
  نرمال‌سازی مخصوص فارسی — «ک/ك»، «ی/ي»، نیم‌فاصله، ارقام فارسی و مشکل لیگاتور «لا» همه یکسان‌سازی می‌شوند.
  اگر بردارسازی در دسترس نباشد، سیستم خودکار روی جستجوی کلیدواژه‌ای ادامه می‌دهد.
- **پاسخ استریمی.** جواب کلمه‌به‌کلمه تایپ می‌شود، نه یک انتظار طولانی و بعد یک دیوار متن.
- **طول پاسخ را کاربر انتخاب می‌کند** — کوتاه / متوسط / کامل. این انتخاب با پرامپت اعمال می‌شود،
  نه با بریدن توکن؛ بنابراین «کوتاه» یعنی پاسخِ جمع‌وجورِ کامل، نه پاسخی که وسط جمله قطع شده.
  در هر حالت، مدل طول را متناسب با خودِ سوال انتخاب می‌کند.
- **سابقه‌ی گفتگو.** هر مرورگر گفتگوهای قبلی خودش را دارد؛ با رفرش صفحه چیزی گم نمی‌شود.
- **تنظیم از داخل پنل.** کلید API و هر چهار مدل از پنل مدیریت قابل تغییرند — بدون ویرایش فایل و
  بدون ری‌استارت سرور — و یک دکمه‌ی «تست اتصال» صحتشان را همان‌جا بررسی می‌کند.
- **دکمه‌ی «بازنویسی برای مشتری».** کارشناس پشتیبانی جواب فنی را می‌گیرد و با یک کلیک
  نسخه‌ی تمیز و قابل ارسال به مشتری را تحویل می‌گیرد.
- **گزارش خلأهای دانش.** هر سوالی که در مستندات پاسخ نداشته یا کاربر آن را بی‌فایده دانسته،
  در پنل مدیریت فهرست می‌شود — یعنی دقیقاً می‌دانید چه چیزی را باید به راهنماها اضافه کنید.
- **بدون Streamlit، بدون build.** رابط کاربری HTML/CSS/JS خالص و راست‌چین است؛ فونت وزیرمتن
  هم داخل پروژه است و به CDN خارجی وابسته نیست.

## راه‌اندازی

### ۱. کلید AvalAI

از پنل [avalai.ir](https://avalai.ir) یک کلید بسازید (با `aa-` شروع می‌شود).

### ۲. گرفتن پروژه

اگر Git دارید:

```bash
git clone -b claude/ai-support-assistant-grtf7b https://github.com/RaminOmrani/AI-Help
cd AI-Help
```

اگر Git ندارید، از صفحه‌ی گیت‌هاب دکمه‌ی **Code ← Download ZIP** را بزنید و از حالت فشرده خارج کنید.

### ۳. اجرا

**ویندوز** — روی فایل `start.bat` دابل‌کلیک کنید. همین.
(یا در cmd، از داخل پوشه‌ی پروژه: `start.bat`)

**لینوکس / مک**

```bash
./start.sh
```

اسکریپت خودش محیط مجازی می‌سازد، وابستگی‌ها را نصب می‌کند، فایل `.env` را از روی نمونه
می‌سازد و سرور را بالا می‌آورد. بار اول چند دقیقه طول می‌کشد. اگر پایتون نصب نباشد،
پیام واضح می‌دهد و متوقف می‌شود.

> ویندوز: هنگام نصب پایتون از [python.org](https://www.python.org/downloads/) حتماً تیک
> **«Add python.exe to PATH»** را بزنید، وگرنه `start.bat` پایتون را پیدا نمی‌کند.

**اجرای دستی** (اگر خواستید مرحله‌به‌مرحله جلو بروید):

```bash
python -m venv venv
source venv/bin/activate        # ویندوز: venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env          # لینوکس/مک: cp .env.example .env
python run.py
```

سرور که بالا آمد، سه آدرس باز می‌شود:

| آدرس | چیست |
|---|---|
| `http://localhost:8000/` | صفحه‌ی مشتری |
| `http://localhost:8000/agent` | کنسول پشتیبان (رمز: `AGENT_PASSWORD`) |
| `http://localhost:8000/admin` | پنل مدیریت (رمز: `ADMIN_PASSWORD`) |

### ۴. وارد کردن کلید — دو راه

**راه ساده (بدون دست زدن به فایل):** وارد `http://localhost:8000/admin` شوید و در تب
**«🔑 کلید و مدل‌ها»** کلید AvalAI را بگذارید و ذخیره کنید. همان‌جا دکمه‌ی **«🔌 تست اتصال»**
هست که کلید، اعتبار تومانی، مدل پاسخ‌دهی، مدل بینایی و مدل بردارسازی را یکی‌یکی تست می‌کند و
اگر جایی ایراد داشت دقیقاً می‌گوید کدام و چرا.

**راه فایل:** در `.env` بگذارید:

```env
AVALAI_API_KEY=aa-xxxxxxxxxxxxxxxx
```

مقدارِ ثبت‌شده در پنل بر `.env` اولویت دارد. برای برگرداندن به حالت `.env`،
در کادر کلیدِ پنل فقط یک خط تیره `-` بگذارید و ذخیره کنید.

> ⚠️ این دو را حتماً در `.env` عوض کنید (از پنل قابل تغییر نیستند):
> ```env
> SECRET_KEY=یک-رشته-تصادفی-طولانی
> ADMIN_PASSWORD=رمز-مدیر
> AGENT_PASSWORD=رمز-کارشناس
> ```

### ۵. تست اتصال از ترمینال

همان تست‌های پنل، از خط فرمان:

```bash
python scripts/check_avalai.py
```

این اسکریپت کلید، اعتبار تومانی، فهرست مدل‌های فعال حساب شما، پاسخ‌دهی، **خواندن تصویر** و بردارسازی را تست می‌کند
و مدل‌های حساب را دسته‌بندی می‌کند (سریع / قوی / بردارسازی) تا انتخاب راحت‌تر شود.

### انتخاب مدل مناسب

نام مدل‌ها مدام عوض می‌شود و هیچ فهرستی زیاد تازه نمی‌ماند. به‌جای حدس زدن، مدل‌ها را روی
مستندات و سوال‌های واقعی خودتان مقایسه کنید:

```bash
python scripts/compare_models.py gemini-3.7-flash gemini-3.5-flash
```

هر مدل چند سوال واقعی را از مسیر کامل RAG رد می‌کند و خروجی شامل **هزینه‌ی واقعی تومانی**
هر مدل (از تفاضل اعتبار حساب AvalAI) به‌همراه یک گزارش HTML برای مقایسه‌ی کنار‌به‌کنارِ پاسخ‌هاست.

```bash
# سوال‌های دلخواه، برای دستیار پشتیبان
python scripts/compare_models.py --audience internal --ask "خطای اتصال به SQL" مدل۱ مدل۲
```

**قاعده‌ی کلی:** این کار «پاسخ از روی مستندات» است، نه استدلال سنگین — مدل رده‌ی سریع
(`flash` / `mini` / `haiku`) تقریباً همیشه کافی است. اگر پاسخ‌ها غلط بودند، معمولاً مشکل از
کیفیت مستندات است نه از مدل.

### ۶. بارگذاری راهنماها

به `http://localhost:8000/admin` بروید، وارد شوید و فایل‌ها را روی کادر بارگذاری بکشید.
اگر فایل‌ها از قبل در پوشه‌ی `docs/` هستند، دکمه‌ی **«وارد کردن پوشه‌ی docs»** همه را یک‌جا اضافه می‌کند.

فرمت‌های پشتیبانی‌شده: `PDF`، `DOCX`، `TXT`، `MD`، `CSV`.

موقع بارگذاری، تیک **«خواندن متن و تصویرهای فایل با هوش مصنوعی»** روشن است. اگر خاموشش کنید،
فقط متنِ خام استخراج می‌شود و اسکرین‌شات‌ها نادیده گرفته می‌شوند.

> 💡 PDF اسکن‌شده هم کار می‌کند، چون صفحه‌ها از روی تصویر خوانده می‌شوند.
> فقط اگر تیک بالا را بردارید، فایل اسکن‌شده «۰ تکه» می‌شود.

## استفاده‌ی روزمره

**مشتری** — فقط `/` را باز می‌کند: سوال می‌پرسد، جواب گام‌به‌گام می‌گیرد،
می‌تواند 👍/👎 بدهد یا با فرم «کارشناس انسانی» درخواست تماس ثبت کند (تیکت در پنل مدیریت دیده می‌شود).
ورودی صوتی فارسی هم دارد (روی مرورگرهای مبتنی بر Chrome).
با دکمه‌ی 🕘 گفتگوهای قبلی‌اش را می‌بیند و هر کدام را می‌تواند باز یا حذف کند؛
با رفرش صفحه هم گفتگوی جاری از بین نمی‌رود.

**کارشناس پشتیبانی** — `/agent`: جواب فنی با ارجاع دقیق می‌گیرد، تکه‌های استفاده‌شده‌ی مستندات را
در پنل کناری با امتیاز مرتبط‌بودن می‌بیند، در تب «جستجوی مستقیم» می‌تواند بدون پرسیدن سوال، داخل
مستندات بگردد، و با دکمه‌ی «بازنویسی برای مشتری» متن آماده‌ی ارسال بگیرد.

**مدیر** — `/admin`: بارگذاری و مدیریت فایل‌ها، تعیین سطح دسترسی هر فایل، **ثبت کلید و انتخاب مدل‌ها
بدون دست زدن به فایل**، تست اتصال، مشاهده‌ی آمار، اعتبار AvalAI، گفتگوها، تیکت‌ها، خلأهای دانش و
ویرایش پیام‌های خوش‌آمد و سوال‌های پیشنهادی.

```
│   ├── textutils.py     نرمال‌سازی فارسی

│   ├── chat_service.py  منطق مشترک گفتگو و سابقه

│   └── security.py      ورود و توکن
├── web/
│   ├── index.html       صفحه‌ی مشتری
│   ├── agent.html       کنسول پشتیبان
│   ├── admin.html       پنل مدیریت
│   └── assets/          استایل، جاوااسکریپت و فونت وزیرمتن
├── scripts/
│   ├── check_avalai.py    تست کلید، اعتبار و مدل‌های حساب
│   ├── compare_models.py  مقایسه‌ی مدل‌ها روی مستندات خودتان
│   └── selftest.py        تست خط لوله بدون نیاز به کلید

└── data/                دیتابیس و فایل‌های بارگذاری‌شده (در گیت نیست)
```

## نکته‌های عملیاتی

- **هزینه.** خواندن تصویری و بازسازی متن فقط یک‌بار موقع بارگذاری هر فایل انجام می‌شود، نه در هر سوال.
  برای راهنمای ۱۱۷ صفحه‌ایِ این پروژه (۹۵ صفحه‌ی عکس‌دار) حدود ۳۰ تا ۵۰ هزار تومان، یک‌بار.
  اگر نمی‌خواهید، تیک «خواندن متن و تصویرهای فایل با هوش مصنوعی» را بردارید یا `VISION_ENABLED=false` بگذارید.
- **سقف امن.** هر فایل حداکثر `VISION_MAX_PAGES` صفحه (پیش‌فرض ۳۰۰) تصویری خوانده می‌شود.
  اگر فایل بزرگ‌تر بود، در لاگ سرور صریحاً گزارش می‌شود که چند صفحه خوانده نشده.
- **انتخاب مدل.** پیش‌فرض `gemini-3.7-flash` است — ارزان، تازه، و در بنچمارک‌های OCR
  و خواندن سند جزو بهترین‌هاست. `VISION_MODEL` حتماً باید مدلی باشد که تصویر می‌فهمد؛
  `python scripts/check_avalai.py` این را با یک تصویر آزمایشی تست می‌کند.
- **انتشار روی سرور.** پشت nginx یا caddy با HTTPS قرار دهید. `SECRET_KEY` را حتماً عوض کنید،
  و اگر صفحه‌ی مشتری عمومی است، `PORT` را فقط از طریق ریورس‌پروکسی باز بگذارید.
- **پشتیبان‌گیری.** تمام داده‌ها در `data/support.db` و `data/uploads/` است؛ همین دو را بکاپ بگیرید.
- **تغییر برند.** `BRAND_NAME`، `BRAND_PRODUCT`، `ASSISTANT_NAME` و `SUPPORT_PHONE` را در `.env` بگذارید.

## API (خلاصه)

| متد | مسیر | توضیح |
|---|---|---|
| `POST` | `/api/chat` | گفتگوی مشتری (SSE) |
| `POST` | `/api/ticket` | ثبت درخواست تماس |
| `POST` | `/api/feedback` | بازخورد 👍/👎 |
| `GET`  | `/api/history` | پیام‌های گفتگوی جاری |
| `GET`  | `/api/conversations` | فهرست گفتگوهای قبلی مرورگر |
| `POST` | `/api/auth/login` | ورود با نقش `admin` یا `agent` |
| `POST` | `/api/agent/chat` | گفتگوی کارشناس (SSE) |
| `POST` | `/api/agent/rewrite` | بازنویسی پاسخ برای مشتری |
| `GET`  | `/api/agent/search` | جستجوی مستقیم در مستندات |
| `POST` | `/api/admin/documents` | بارگذاری فایل |
| `GET`  | `/api/admin/credit` | مانده‌ی اعتبار AvalAI |
| `PUT`  | `/api/admin/ai-settings` | ثبت کلید و مدل‌ها |
| `POST` | `/api/admin/ai-test` | تست اتصال |
| `GET`  | `/api/admin/gaps` | سوال‌های بی‌پاسخ |

مستندات کامل و تعاملی: `http://localhost:8000/docs`
